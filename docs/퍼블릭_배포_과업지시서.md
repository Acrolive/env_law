# env_law 퍼블릭 배포 과업지시서 및 출시 검증 기준

## 1. 문서 목적

이 문서는 `env_law` 저장소를 GitHub 공개 저장소로 안전하게 배포하기 위해 필요한 수정 과업, 검증 방법, 증빙 산출물 및 최종 출시 승인 기준을 정의한다.

공개 배포의 의미는 다음 두 조건을 모두 충족하는 상태로 한정한다.

1. 저장소의 추적 파일과 전체 Git 이력에 API 식별정보, 세션 기록, 사용자 질의 등 비공개 정보가 없다.
2. 지원 환경에서 설치, 국가법령정보 API 호출, 순차 하네스, Codex 및 Claude Code 어댑터가 재현 가능하게 동작한다.

이 시스템은 법령 리서치 보조도구이며 법률적 결론의 정확성을 자동 보증하지 않는다. 공개 배포 승인도 법률 자문 품질에 대한 인증이 아니라 소프트웨어 배포·보안·호환성 게이트 통과를 의미한다.

## 2. 현재 기준선과 잠정 판정

기준일: 2026-10-12

현재 확인된 상태는 다음과 같다.

- 오프라인 테스트: 10건 통과
- 라이브 국가법령정보 API 테스트: 9건 통과
- Bash, Python, Node.js 문법 검사: 통과
- 깨끗한 임시 디렉터리의 `npm ci`: 통과
- Codex 네이티브 에이전트 순차 실행: 실제 성공 사례 있음
- Claude Code 설치 진단: 문제 없음
- 현재 잠금 의존성 감사: critical 1건, high 9건, moderate 7건, low 1건
- `kordoc` 최신 안정 버전 후보로 임시 갱신한 감사: 취약점 0건
- 실제 `LAW_API_OC`가 로컬 `.env`, `.omc/`, `.omx/` 일부 로그·상태 파일에 존재
- 현재 Git 커밋 후보와 로컬 Git 이력에서는 실제 OC 미검출
- `.omx/`는 프로젝트 `.gitignore`가 아니라 로컬 `.git/info/exclude`에만 등록됨
- `npm pack --dry-run` 결과 일부 `.omx/state` 파일이 패키지 대상에 포함됨
- 핵심 하네스·Codex 파일이 아직 미추적 상태이며 기존 파일도 다수 수정 상태
- 프로젝트 루트에 `LICENSE`, `SECURITY.md`, GitHub Actions 워크플로가 없음

따라서 현재 판정은 **배포 보류**다. 아래 모든 필수 게이트를 통과한 경우에만 `RELEASE_READY`로 변경한다.

## 3. 수행 원칙

1. 실제 OC, API URL의 실제 `OC=` 값, 사용자 질의 원문 또는 세션 로그를 화면·커밋·CI 로그·검증 보고서에 출력하지 않는다.
2. 비밀정보 검사 결과는 값이 아니라 파일 경로, 커밋 식별자, 탐지 규칙만 기록한다.
3. 기존 OC가 로그에 노출된 사실이 확인되었으므로 코드 정리보다 먼저 기존 OC를 교체한다.
4. `.env`를 셸 코드로 실행하지 않고 `scripts/load_law_env.sh`만 사용한다.
5. 라이브 API 테스트는 신뢰된 브랜치의 수동 실행 또는 예약 실행에서만 수행한다. 외부 포크 PR에는 API 값을 제공하지 않는다.
6. Codex와 Claude Code의 검색→검증→초안→평가는 반드시 순차 실행한다.
7. 별표 파싱 변경은 HWP와 PDF 대조 테스트 없이 승인하지 않는다.
8. GitHub 공개 전 최종 검사는 공개 예정 커밋의 깨끗한 신규 클론에서 수행한다.

## 4. 과업 범위

### WP-01. 자격정보 교체 및 로컬 비밀정보 제거

#### 수행 내용

1. 국가법령정보 OpenAPI 관리 화면에서 기존 `LAW_API_OC`를 교체하거나 기존 값의 사용을 중지한다.
2. 새 OC는 Git 저장소 밖의 사용자 환경변수 또는 권한이 제한된 `.env`에만 저장한다.
3. `.env` 파일 권한을 소유자만 읽고 쓸 수 있도록 제한한다.
4. `.omc/`, `.omx/`, `.harness/`에서 배포에 필요하지 않은 세션·로그·상태 파일을 제거한다.
5. 보존이 필요한 검증 증빙은 OC와 사용자 질의를 제거한 요약본으로 새로 작성한다. 원본 로그를 수정해 공개 증빙으로 재사용하지 않는다.

#### 검증 명령

```bash
chmod 600 .env
stat -c '%a %n' .env
```

합격값은 `600 .env`다.

새 OC의 정확한 값이 저장소 파일에 복제되지 않았는지는 값을 출력하지 않는 다음 방식으로 검사한다.

```bash
source scripts/load_law_env.sh
load_law_env .env
test -n "${LAW_API_OC:-}"

git ls-files -z |
  xargs -0 grep -IlF -- "$LAW_API_OC"

commits=$(git rev-list --all)
git grep -l -F -- "$LAW_API_OC" $commits 2>/dev/null || true
```

두 검사 모두 출력이 없어야 한다. 명령 자체와 CI 로그에 실제 값을 표시해서는 안 된다.

#### 완료 기준

- 기존 OC 교체 또는 폐기 증빙이 비공개 운영 기록에 남아 있다.
- `.env` 권한이 `600`이다.
- 공개 예정 파일 및 전체 Git 이력에서 현재 OC와 이전 OC가 모두 검출되지 않는다.
- 런타임 로그를 저장소 또는 배포 패키지에 포함하지 않는다.

### WP-02. Git 및 패키징 제외 규칙 강화

#### 수행 내용

프로젝트 `.gitignore`에 최소한 다음 항목을 명시한다.

```gitignore
.env
.env.*
!.env.example
.harness/
.omc/
.omx/
node_modules/
__pycache__/
*.py[cod]
*.log
*.jsonl
data/annex_samples/
```

로컬 `.git/info/exclude`는 공개 저장소의 보안 통제로 인정하지 않는다.

GitHub 배포만 지원하고 npm 공개 배포를 하지 않는다면 `package.json`에 다음을 설정한다.

```json
{
  "private": true
}
```

npm 공개 배포도 필요하다면 별도 승인을 받고 `private`을 제거하되, `files` 허용목록 또는 `.npmignore`를 추가하고 `prepack` 비밀정보 게이트를 구현한다.

#### 검증 명령

```bash
git check-ignore -v \
  .env .harness .omc .omx node_modules \
  scripts/__pycache__ tests/__pycache__

npm pack --dry-run --json
```

`npm pack --dry-run` 출력에는 다음 경로가 한 건도 없어야 한다.

- `.env`
- `.harness/`
- `.omc/`
- `.omx/`
- `node_modules/`
- 세션·로그·캐시 파일

#### 완료 기준

- 모든 런타임 디렉터리가 프로젝트 `.gitignore`에서 제외된다.
- GitHub 전용 배포이면 `private: true`가 설정된다.
- npm 패키징 대상에 런타임 파일과 비밀정보가 없다.

### WP-03. 전체 Git 이력 비밀정보 검사

#### 수행 내용

1. Gitleaks 또는 동등한 도구로 작업트리, 스테이징 영역 및 전체 Git 이력을 검사한다.
2. 국가법령정보 OC는 일반적인 고엔트로피 토큰이 아닐 수 있으므로 사용자 정의 탐지 규칙을 추가한다.
3. 다음 패턴을 최소 탐지 대상으로 포함한다.
   - `LAW_API_OC=<비어 있지 않은 값>`
   - URL 쿼리의 `OC=<OC 또는 신청자 ID>`
   - 확인된 이전 OC와 현재 OC의 정확 일치
4. 테스트 픽스처의 `test-user`, `secret-user`, `<OC>`, `<redacted>`는 경로와 값이 명확한 경우에만 허용목록으로 관리한다.

#### 검증 명령 예시

```bash
gitleaks git --redact --verbose
gitleaks dir . --redact --verbose
```

`--redact`를 제거하지 않는다.

#### 완료 기준

- 작업트리와 전체 이력 검사 결과가 0건이다.
- 허용목록은 테스트용 고정 문자열에만 적용된다.
- 실제 OC를 허용목록에 넣지 않는다.

### WP-05. Codex 스킬의 크로스플랫폼 배포 구조 정리

#### 수행 내용

현재 `.codex/skills/auto-research-env-law` 심볼릭 링크는 Linux에서는 동작하지만 Windows Git 설정에 따라 일반 텍스트 파일로 체크아웃될 수 있다.

다음 중 하나로 변경한다.

1. 권장: `.codex/skills/auto-research-env-law/SKILL.md`를 실제 파일인 얇은 어댑터로 두고 `.agents/skills/auto-research-env-law` 공통 계약을 명시적으로 호출한다.
2. 대안: 공통 스킬을 `.codex/skills`에 실제 디렉터리로 배치하고 동기화 검사를 추가한다.

심볼릭 링크 유지 방식은 Windows 미지원이라고 README에 명확히 제한하지 않는 한 승인하지 않는다.

#### 검증 항목

- Linux 신규 클론에서 스킬이 발견된다.
- Windows 또는 `core.symlinks=false` 신규 클론에서 `SKILL.md`가 정상 파일로 존재한다.
- `$auto-research-env-law` 명시 호출이 공통 계약을 읽는다.
- 세 역할 `env_law_researcher`, `env_law_verifier`, `env_law_evaluator`가 발견된다.

#### 완료 기준

- 심볼릭 링크 설정과 무관하게 스킬이 로드된다.
- 공통 계약 원본이 하나라는 구조적 원칙이 유지되거나, 복제본 동기화 테스트가 존재한다.

### WP-06. Claude Code 계약 불일치 제거

#### 수행 내용

1. `.claude/agents/law-verifier.md` 출력 예시에 `iteration` 필드를 추가한다.
2. `.claude/agents/persona-evaluator.md` 출력 예시에 `iteration` 필드를 추가한다.
3. Claude 스킬이 verifier에게 원 질의, 반복 번호, researcher JSON 전체를 전달하도록 명시한다.
4. evaluator에게 원 질의, 반복 번호, 검증 통과 evidence, 초안을 전달하도록 명시한다.
5. `.claude/skills`와 `.claude/agents`의 예시 JSON이 `references/contract.md`와 다르면 테스트를 실패시킨다.
6. `CLAUDE.md`, Claude 스킬 및 공통 계약에 서로 다른 단계 순서가 남지 않도록 한다.

#### 완료 기준

- Claude 역할 문서의 필수 필드가 공통 계약과 일치한다.
- verifier 거부 반복에는 draft와 evaluation이 생성되지 않는다.
- 동일 반복에서 `researcher → verifier → draft → evaluation` 순서가 강제된다.

### WP-07. API 래퍼 입력 검증 및 로그 안전성 강화

#### 수행 내용

1. `target`, `MST/ID`, 조번호, 시행일, 별표번호, 출력 형식을 허용목록으로 검증한다.
2. 사용자 입력을 Python `-c` 소스 문자열에 직접 보간하지 않는다. 위치 인자 또는 표준입력으로 전달한다.
3. 오류 응답 본문을 그대로 로그에 출력하기 전에 민감정보 마스킹을 적용한다.
4. 라이브 테스트의 `/tmp/t_*.json` 고정 파일 대신 `mktemp -d`를 사용한다.
5. 종료 시 임시 파일 정리용 `trap`을 사용한다.
6. API 캐시 디렉터리와 파일 권한을 사용자 전용으로 제한한다.

#### 완료 기준

- 따옴표, 줄바꿈, 추가 쿼리 파라미터가 포함된 잘못된 입력이 안전하게 거부된다.
- 입력값으로 임의 Python 코드가 실행되지 않는다.
- 실패 로그에 실제 OC가 포함되지 않는다.
- 다중 사용자 환경에서 다른 사용자가 캐시를 읽거나 덮어쓸 수 없다.

5. URL 인코딩·대소문자·다른 필드명에 대한 OC 마스킹 우회 검사
6. API 래퍼 입력 검증 및 Python 코드 삽입 방지 검사

10. 라이브 API 응답 스키마가 예상과 다를 때 안전하게 실패하는 검사

#### 릴리스 게이트 스크립트

`scripts/release_gate.sh`를 작성한다. 기본 실행은 비밀정보를 요구하지 않는 오프라인 게이트로 구성한다.

```bash
./scripts/release_gate.sh
./scripts/release_gate.sh --live
```

기본 게이트는 최소한 다음을 수행한다.

- Git 작업트리 상태 확인
- 금지 파일 추적 여부 확인
- Bash/Python/Node 문법 검사
- 오프라인 테스트
- 프로덕션 의존성 보안 감사
- npm 패키징 대상 검사
- 스킬·에이전트 계약 정합성 검사

`--live`는 신뢰된 환경에서만 API 테스트 및 Codex·Claude Code E2E 검사를 추가한다.

#### 완료 기준

- 어느 단계든 실패하면 즉시 비영(0이 아닌) 종료코드를 반환한다.
- 실제 OC를 표준출력, 표준오류 또는 결과 파일에 기록하지 않는다.
- 실행 결과에 단계별 PASS/FAIL과 실패 원인만 표시한다.

### WP-09. Codex 및 Claude Code 실제 E2E 검증

모델 호출 비용과 계정 자격이 필요한 게이트이므로 릴리스 담당자가 명시적으로 실행한다. 테스트 전 `umask 077`을 적용하고 세션 영구 저장을 비활성화한다.

#### 공통 시험 질의

다음 유형을 최소 3건 사용한다.

1. 법령→시행령→시행규칙→고시 계층 확인이 필요한 질의
2. 별표 HWP/PDF 검증이 필요한 질의
3. 관련 근거가 없어 `근거 미확인`으로 종료되어야 하는 질의

실제 사업장명, 개인정보, 영업비밀은 시험 질의에 사용하지 않는다.

#### Codex 실행 예시

```bash
umask 077
codex exec \
  --ephemeral \
  --json \
  --sandbox workspace-write \
  --cd "$PWD" \
  'Use $auto-research-env-law for this synthetic test question: <시험 질의>'
```

#### Claude Code 실행 예시

```bash
umask 077
claude --print \
  --no-session-persistence \
  --output-format stream-json \
  --permission-mode auto \
  --max-budget-usd 5 \
  '/auto-research-env-law <시험 질의>'
```

실행 환경의 권한정책에 맞지 않으면 위험한 우회 옵션을 사용하지 말고 대화형으로 필요한 읽기·API 호출만 승인한다.

#### E2E 합격 기준

- 올바른 스킬이 명시 호출 또는 의도된 자동 라우팅으로 활성화된다.
- 역할이 researcher→verifier→evaluator 순서로 호출된다.
- verifier 실패 시 같은 반복의 draft/evaluation이 없다.
- 합격 실행은 하네스 상태가 `accepted`다.
- 90점 미달 실행은 `partial`, 4회 연속 검증 실패는 `failed`다.
- 모든 인용은 검증 통과 evidence에만 존재한다.
- 실제 OC가 출력·세션·하네스 파일에 없다.
- Codex와 Claude Code의 핵심 결론 및 근거 식별자가 실질적으로 일치한다.

### WP-10. GitHub CI/CD 및 저장소 보호 설정

#### 필수 워크플로

1. `ci.yml`
   - Ubuntu
   - Node.js 20.9 이상
   - Python 3.11 이상
   - `npm ci`
   - 문법 검사
   - `npm test`
   - `npm audit --omit=dev`
   - 패키징 금지 경로 검사
2. `secret-scan.yml`
   - PR, push, 수동 실행
   - 전체 이력 Gitleaks 검사
3. `live-api.yml`
   - 수동 실행 또는 예약 실행
   - 저장소 secret에서만 OC 주입
   - 외부 포크 PR에서는 실행 금지

#### GitHub 설정

- 공개 전 GitHub Secret Scanning 및 Push Protection 활성화
- Dependabot 또는 동등한 의존성 업데이트 자동화 활성화
- `main` 브랜치 보호 및 필수 CI 체크 설정
- 직접 push 제한 또는 리뷰 1인 이상 요구
- Actions 로그 보존기간 최소화
- 외부 포크에 secret이 전달되지 않는지 확인

#### 완료 기준

- 비밀정보 없이 PR CI가 재현된다.
- 라이브 테스트는 승인된 실행에서만 동작한다.
- 필수 게이트 실패 시 `main` 병합이 차단된다.

### WP-11. 공개 문서·라이선스·책임 범위 정리

#### 수행 내용

1. 저작권자가 공개 라이선스를 확정한다.
2. `package.json`의 `ISC`를 유지한다면 정식 `LICENSE` 파일을 추가한다. 다른 라이선스를 선택하면 두 위치를 함께 변경한다.

4. README에 다음 내용을 반영한다.
   - 지원 OS와 Windows 제한 여부
   - Node.js 20.9 이상
   - Python, curl, pdftotext 요구사항
   - API OC 보관 및 교체 방법
   - 로그에 민감정보를 넣지 않는 방법
   - Codex·Claude Code 최소 검증 버전
   - 법률적 정확성 비보증과 사람의 최종 검토 필요성

#### 완료 기준

- 라이선스 파일과 패키지 메타데이터가 일치한다.
- 보안 신고 채널이 존재한다.
- 신규 사용자가 README만으로 설치 및 기본 검증을 완료할 수 있다.
- 법령 데이터 및 포함 데이터셋의 재배포 조건이 확인된다.

### WP-12. 깨끗한 신규 클론 최종 검증

모든 변경을 커밋한 후 현재 작업 디렉터리가 아닌 새 임시 디렉터리에서 검증한다.

```bash
release_clone=$(mktemp -d -p /tmp env-law-release.XXXXXX)
git clone --no-local . "$release_clone/repo"
cd "$release_clone/repo"

npm ci
./scripts/release_gate.sh
```

신뢰된 환경에서만 새 `.env`를 생성하고 다음을 추가 실행한다.

```bash
chmod 600 .env
./scripts/release_gate.sh --live
```

#### 완료 기준

- 로컬 전역 설정, `.git/info/exclude`, 기존 `node_modules`, API 캐시 또는 세션 상태 없이 통과한다.
- 공개 예정 커밋 SHA가 검증 보고서의 SHA와 일치한다.
- 최종 클론에 금지 경로가 없다.

## 5. 최종 배포 승인 게이트

다음 표의 모든 필수 항목이 PASS여야 한다.

| 게이트 | 필수 조건 | 판정 |
|---|---|---|
| G-01 Git 상태 | 공개 예정 변경이 모두 검토·커밋되고 작업트리가 깨끗함 | 필수 |
| G-02 비밀정보 | 현재/이전 OC가 작업트리·Git 이력·패키지에 없음 | 필수 |
| G-03 런타임 산출물 | `.env/.omc/.omx/.harness`가 Git·패키지에서 제외됨 | 필수 |
| G-04 의존성 | 프로덕션 `npm audit` 0건 | 필수 |
| G-05 재현 설치 | Node 20.9+ 신규 클론에서 `npm ci` 성공 | 필수 |
| G-06 오프라인 테스트 | 모든 단위·계약·보안 테스트 통과 | 필수 |
| G-07 라이브 API | 모든 라이브 회귀 테스트 통과 | 필수 |
| G-08 Codex E2E | 3개 대표 질의 및 상태 계약 통과 | 필수 |
| G-09 Claude E2E | 3개 대표 질의 및 상태 계약 통과 | 필수 |
| G-10 크로스플랫폼 | Linux 및 지원 대상 OS에서 스킬 발견 확인 | 필수 |
| G-11 CI 보호 | PR CI·비밀검사·브랜치 보호 활성화 | 필수 |
| G-12 문서·법무 | LICENSE, SECURITY, README, 데이터 재배포 조건 확인 | 필수 |

다음 중 하나라도 해당하면 즉시 `RELEASE_BLOCKED`다.

- 실제 OC 또는 이전 OC 탐지
- critical/high/moderate/low 중 하나라도 프로덕션 감사에 남음
- 외부 포크 PR에 live secret 전달 가능
- npm 패키지 또는 Git에 런타임 상태 파일 포함
- Codex 또는 Claude Code E2E에서 단계 순서 위반
- verifier가 거부한 evidence가 최종 답변에 포함
- 지원한다고 명시한 OS에서 스킬이 발견되지 않음
- 라이선스 또는 포함 데이터의 재배포 권한 미확인

## 6. 필수 산출물

1. 보안 수정 커밋
2. 의존성 및 잠금파일 갱신 커밋
3. 플랫폼 계약 정합화 커밋
4. GitHub Actions 워크플로
5. `scripts/release_gate.sh`
6. 강화된 단위·회귀·패키징 테스트
7. `LICENSE`
8. `SECURITY.md`
9. 갱신된 README
10. `docs/퍼블릭_배포_검증보고서.md`

검증보고서에는 다음만 기록한다.

- 공개 예정 커밋 SHA
- 실행 일시와 OS·도구 버전
- 각 게이트의 PASS/FAIL
- 테스트 개수와 종료코드
- 의존성 감사 요약
- E2E 실행 ID와 하네스 최종 상태
- 남은 제한사항

실제 OC, `.env` 내용, 전체 사용자 질의, 원본 세션 로그는 기록하지 않는다.

## 8. 종료 조건

과업은 다음 조건을 모두 충족할 때 완료된다.

1. G-01부터 G-12까지 모두 PASS다.
2. 깨끗한 신규 클론에서 동일 결과가 재현된다.
3. 기존 OC가 교체 또는 폐기되었다.
4. 공개 예정 커밋과 검증된 커밋이 동일하다.

검증 이후 커밋이 변경되면 기존 승인은 무효이며, 변경된 커밋으로 전체 릴리스 게이트를 다시 실행한다.
